## 구현과 문서의 차이 (2026-11-25, 10단계 완료 시점)
설계 문서는 v1.0 그대로이고, 개발 중 사용자 결정으로 아래가 추가·변경됐습니다. 실제 기준은 코드(`engine/config.py`, `server/app.py`)입니다.
| 항목 | 문서 v1.0 | 실제 구현 |
|---|---|---|
| 노트 쪽수 | 0~50 | 화면·서버 1~50 (엔진은 0 허용) |
| 기간 | 1년 | 시작 달 + 1~18개월 |
| 테마 | 4종 | 8종 + 메인색 직접 고르기 |
| 추가 기능 | — | 공휴일, 추가 페이지 4종, 속지 선택, 글꼴 5종, 표지 글 |
| 서버 | 제안 | Render 무료(Docker), 생성 결과에 한국어·영어 상품 문구 포함 |
| 이력 | 서버 저장 검토 | 로그인 없이 브라우저에만 저장 |

## 핵심 결정
- PC·태블릿·스마트폰 웹 브라우저를 지원하는 반응형 UI를 제품 요구사항으로 정의합니다.
- 웹 브라우저에서 PDF 생성 기능을 제공하려면 Python 엔진을 호출하는 서버 API가 필요합니다.
- Electron IPC 경로는 유지하고 웹 API 경로를 별도로 추가합니다.
- 반응형 UI 완료와 웹 PDF 생성 완료는 별도로 검증합니다.
- REST API는 구현 현황이 아닌 모바일 웹 전환을 위한 설계 제안으로 구분합니다.

## 문서 변경 규칙
- 화면·레이아웃·사용자 흐름 변경 시 UI 설계서를 함께 갱신합니다.
- 색상·타이포그래피·간격·컴포넌트 규칙 변경 시 디자인 시스템과 HTML 시안을 함께 갱신합니다.
- 기능·입력값·검증 규칙 변경 시 기능정의 및 API 설계를 함께 갱신합니다.
- 코드 변경으로 설계 기준이 달라지면 동일 변경 작업에서 문서를 갱신하고 변경 이력을 기록합니다.
- 문서와 구현이 불일치하면 구현 완료로 처리하지 말고 차이를 기록한 뒤 정합성을 맞춥니다.
